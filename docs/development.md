# Development

Complete the [repository setup](../README.md#quick-start). Run commands from the repository root unless a section says otherwise.

## Workspace

Applications live in `apps/*`; published packages live in `packages/*`. Install dependencies from the root.

External dependency versions belong in the root `package.json` catalog. Workspace manifests use `catalog:` for external packages and `workspace:*` for local packages. After dependency changes, run:

```sh
bun run deps:sync
```

Runtime package exports point at `dist/`. The root `dev` and `dev:worker` scripts build shared packages first, watch them, and start the selected application. When running an application directly, build packages first:

```sh
bun run build:packages
```

Consumers outside this workspace use packages from npm. Follow the [release process](releases.md) before updating their dependencies.

## Web

Copy `apps/web/.env.development.example` to `apps/web/.env.development.local`. The frontend runs at `http://localhost:3001`.

With `PUBLIC_API_URL` empty, frontend requests use `/api`, which Vite proxies to `http://localhost:3000`. Set an API origin to use another backend. `PUBLIC_COOKIE_DOMAIN` is optional.

All `PUBLIC_*` values are included in browser code. Keep private credentials in server-side configuration.

Edit routes under `apps/web/src/routes/`; `routeTree.gen.ts` is generated by the router plugin.

### Browser tests

From `apps/web`:

```sh
bun x --no-install playwright install
bun run test:browser
```

Playwright builds packages and the browser fixtures, then starts a preview server on port 43180. Projects cover Chromium, Firefox, WebKit, and mobile browser profiles. Traces and screenshots are retained for failures.

| Directory       | Purpose                                                 |
| --------------- | ------------------------------------------------------- |
| `e2e/browser/`  | Vite pages and workers using browser APIs               |
| `e2e/node/`     | Playwright tests, request mocks, and fixture generation |
| `e2e/fixtures/` | Authored beatmaps and generated audio                   |

The web `tsc` script checks the browser and Node test environments separately. Browser tests run through `test:browser`; they are separate from the root `check` command's unit tests.

For the manual lab, run `bun run dev:preview` from `apps/web` and open [the preview page](http://127.0.0.1:43179/e2e/browser/preview.html). This command builds shared packages first. Local beatmaps and music stay in the browser; the lab uses the site's theme provider and components.

## Worker

Copy `apps/worker/.dev.vars.example` to `apps/worker/.dev.vars` and set `API_ORIGIN`.

The Worker matches crawler requests for bundle and user pages, requests preview HTML from the API, and forwards other requests upstream. Routes and production variables live in `apps/worker/wrangler.toml`.

After changing bindings, regenerate the types:

```sh
bun run --cwd apps/worker types
```

`build:worker` uses Wrangler's dry run and does not deploy.

## API reference

The reference site builds from `apps/openapi/openapi.json`. To update it, import an exported public contract:

```sh
bun run --cwd apps/openapi spec:import <generated-openapi.json>
bun run --cwd apps/openapi test
bun run dev:openapi
```

The import validates OpenAPI and rejects external schema references. Review the public diff before committing; include only the contract, without implementation or environment files.

`dev:openapi` builds the site and serves it at `http://127.0.0.1:4173/`; run it again after changing the contract.

## Verification

Use the check that covers the change:

| Command                               | Coverage                                                                                                   |
| ------------------------------------- | ---------------------------------------------------------------------------------------------------------- |
| `bun run check`                       | Dependency policy, package build and release metadata, types, lint, formatting, unit tests, and app builds |
| `bun run check:packages`              | Dependency policy, package builds, types, and package tests                                                |
| `bun run --cwd apps/web test:browser` | Browser integration and chart preview behavior                                                             |
| `bun run release:check`               | Package checks, formatting, lint, release metadata, and packed consumer checks                             |

See [package notes](packages.md), [releases](releases.md), and [deployment](deployment.md).
